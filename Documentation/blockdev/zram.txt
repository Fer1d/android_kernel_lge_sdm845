zram: Compressed RAM based block devices
----------------------------------------

* Introduction

The zram module creates RAM based block devices named /dev/zram<id>
(<id> = 0, 1, ...). Pages written to these disks are compressed and stored
in memory itself. These disks allow very fast I/O and compression provides
good amounts of memory savings. Some of the usecases include /tmp storage,
use as swap disks, various caches under /var and maybe many more :)

Statistics for individual zram devices are exported through sysfs nodes at
/sys/block/zram<id>/

* Temporary ownership diagnostics (disabled by default)

With CONFIG_SWAP=y, the explicit kernel command-line option
swap_owner_diag=1 enables ZRAM_OWNER_DIAG messages from boot for swapon,
swapoff, zram disksize/reset sysfs writes, and internal device resets
(including device removal). swap_owner_diag=0 (or omitting
the option) leaves diagnostics disabled. Do not enable it automatically in
build scripts, defconfigs, boot images, or normal deployments. This is a
boot-only diagnostic option, not a zram module parameter. Modular zram uses
the same exported switch; CONFIG_SWAP=n leaves these diagnostics disabled.

Messages contain op/phase, pid/tgid/comm and real-parent ppid/pcomm copied
under RCU, and the true return code on exit (sysfs success returns the write
length). Entry/target rc=0 is a placeholder, not a success result. Swap paths
are logged only after successful getname(), limited to 128 bytes; early
failures use <unavailable>. Parent identity is a snapshot, not ancestry
history. printk supplies timestamps; there is no additional clock sampling
or global rate limiting, so restrict log access and enable only temporarily.

Zram messages include device, request (up to 64 input bytes), actual, old,
new and totalram (sizes in bytes). For disksize, actual is the selected size
(page-aligned once allocation is attempted), including any
CONFIG_ZRAM_HARDCODE_DISKSIZE override; only a successful exit means it was
applied. For reset, actual is the parsed reset value, not a byte count.
Internal resets use op=internal_reset, request=<internal>, actual=0 and
phase=entry/noop/cleared/done; noop means the device was not initialized.
cleared records old->0 under init_lock, while done means cleanup completed
and its new value is only a later snapshot, possibly after reinitialization.
These internal events have rc=0 because the reset routine returns void.
Entry actual=0 is a placeholder. old/new are observations, not a new
synchronization guarantee; concurrent requests may interleave. The request
is bounded but not escaped, as are swap paths; embedded newlines can split
log lines. Use exit rc to distinguish rejected EBUSY
requests from successful changes. No reset protection or sizing policy is
changed by this option. Collect the kernel log from boot with sufficient
buffer capacity; no collection or boot-option activation is automatic.

* Usage

There are several ways to configure and manage zram device(-s):
a) using zram and zram_control sysfs attributes
b) using zramctl utility, provided by util-linux (util-linux@vger.kernel.org).

In this document we will describe only 'manual' zram configuration steps,
IOW, zram and zram_control sysfs attributes.

In order to get a better idea about zramctl please consult util-linux
documentation, zramctl man-page or `zramctl --help'. Please be informed
that zram maintainers do not develop/maintain util-linux or zramctl, should
you have any questions please contact util-linux@vger.kernel.org

Following shows a typical sequence of steps for using zram.

WARNING
=======
For the sake of simplicity we skip error checking parts in most of the
examples below. However, it is your sole responsibility to handle errors.

zram sysfs attributes always return negative values in case of errors.
The list of possible return codes:
-EBUSY	-- an attempt to modify an attribute that cannot be changed once
the device has been initialised. Please reset device first;
-ENOMEM	-- zram was not able to allocate enough memory to fulfil your
needs;
-EINVAL	-- invalid input has been provided.

If you use 'echo', the returned value that is changed by 'echo' utility,
and, in general case, something like:

	echo 3 > /sys/block/zram0/max_comp_streams
	if [ $? -ne 0 ];
		handle_error
	fi

should suffice.

1) Load Module:
	modprobe zram num_devices=4
	This creates 4 devices: /dev/zram{0,1,2,3}

num_devices parameter is optional and tells zram how many devices should be
pre-created. Default: 1.

2) Set max number of compression streams
Regardless the value passed to this attribute, ZRAM will always
allocate multiple compression streams - one per online CPUs - thus
allowing several concurrent compression operations. The number of
allocated compression streams goes down when some of the CPUs
become offline. There is no single-compression-stream mode anymore,
unless you are running a UP system or has only 1 CPU online.

To find out how many streams are currently available:
	cat /sys/block/zram0/max_comp_streams

3) Select compression algorithm
Using comp_algorithm device attribute one can see available and
currently selected (shown in square brackets) compression algorithms,
change selected compression algorithm (once the device is initialised
there is no way to change compression algorithm).

Examples:
	#show supported compression algorithms
	cat /sys/block/zram0/comp_algorithm
	lzo [lz4]

	#select lzo compression algorithm
	echo lzo > /sys/block/zram0/comp_algorithm

For the time being, the `comp_algorithm' content does not necessarily
show every compression algorithm supported by the kernel. We keep this
list primarily to simplify device configuration and one can configure
a new device with a compression algorithm that is not listed in
`comp_algorithm'. The thing is that, internally, ZRAM uses Crypto API
and, if some of the algorithms were built as modules, it's impossible
to list all of them using, for instance, /proc/crypto or any other
method. This, however, has an advantage of permitting the usage of
custom crypto compression modules (implementing S/W or H/W compression).

4) Set Disksize
Set disk size by writing the value to sysfs node 'disksize'.
The value can be either in bytes or you can use mem suffixes.
Examples:
	# Initialize /dev/zram0 with 50MB disksize
	echo $((50*1024*1024)) > /sys/block/zram0/disksize

	# Using mem suffixes
	echo 256K > /sys/block/zram0/disksize
	echo 512M > /sys/block/zram0/disksize
	echo 1G > /sys/block/zram0/disksize

Note:
There is little point creating a zram of greater than twice the size of memory
since we expect a 2:1 compression ratio. Note that zram uses about 0.1% of the
size of the disk when not in use so a huge zram is wasteful.

5) Set memory limit: Optional
Set memory limit by writing the value to sysfs node 'mem_limit'.
The value can be either in bytes or you can use mem suffixes.
In addition, you could change the value in runtime.
Examples:
	# limit /dev/zram0 with 50MB memory
	echo $((50*1024*1024)) > /sys/block/zram0/mem_limit

	# Using mem suffixes
	echo 256K > /sys/block/zram0/mem_limit
	echo 512M > /sys/block/zram0/mem_limit
	echo 1G > /sys/block/zram0/mem_limit

	# To disable memory limit
	echo 0 > /sys/block/zram0/mem_limit

6) Activate:
	mkswap /dev/zram0
	swapon /dev/zram0

	mkfs.ext4 /dev/zram1
	mount /dev/zram1 /tmp

7) Add/remove zram devices

zram provides a control interface, which enables dynamic (on-demand) device
addition and removal.

In order to add a new /dev/zramX device, perform read operation on hot_add
attribute. This will return either new device's device id (meaning that you
can use /dev/zram<id>) or error code.

Example:
	cat /sys/class/zram-control/hot_add
	1

To remove the existing /dev/zramX device (where X is a device id)
execute
	echo X > /sys/class/zram-control/hot_remove

8) Stats:
Per-device statistics are exported as various nodes under /sys/block/zram<id>/

A brief description of exported device attributes. For more details please
read Documentation/ABI/testing/sysfs-block-zram.

Name            	access            description
----            	------            -----------
disksize          	RW	show and set the device's disk size
initstate         	RO	shows the initialization state of the device
reset             	WO	trigger device reset
mem_used_max      	WO	reset the `mem_used_max' counter (see later)
mem_limit         	WO	specifies the maximum amount of memory ZRAM can use
				to store the compressed data
writeback_limit   	WO	specifies the maximum amount of write IO zram can
				write out to backing device as 4KB unit
writeback_limit_enable  RW	show and set writeback_limit feature
max_comp_streams  	RW	the number of possible concurrent compress operations
comp_algorithm    	RW	show and change the compression algorithm
compact           	WO	trigger memory compaction
debug_stat        	RO	this file is used for zram debugging purposes
backing_dev	  	RW	set up backend storage for zram to write out
idle		  	WO	mark allocated slot as idle
new			WO	write "all" to clear idle flags and counts
idle_stat		RO	allocated slots with 1..10 cumulative idle markings
new_stat		RO	allocated slots with zero idle markings
low_compress_ratio	RW	global minimum memory-saving percentage (default 75)


User space is advised to use the following files to read the device statistics.

File /sys/block/zram<id>/stat

Represents block layer statistics. Read Documentation/block/stat.txt for
details.

File /sys/block/zram<id>/io_stat

The stat file represents device's I/O statistics not accounted by block
layer and, thus, not available in zram<id>/stat file. It consists of a
single line of text and contains the following stats separated by
whitespace:
 failed_reads     the number of failed reads
 failed_writes    the number of failed writes
 invalid_io       the number of non-page-size-aligned I/O requests
 notify_free      Depending on device usage scenario it may account
                  a) the number of pages freed because of swap slot free
                  notifications or b) the number of pages freed because of
                  REQ_DISCARD requests sent by bio. The former ones are
                  sent to a swap block device when a swap slot is freed,
                  which implies that this disk is being used as a swap disk.
                  The latter ones are sent by filesystem mounted with
                  discard option, whenever some data blocks are getting
                  discarded.

File /sys/block/zram<id>/mm_stat

The stat file represents device's mm statistics. It consists of a single
line of text and contains the following stats separated by whitespace:
 orig_data_size   uncompressed size of data stored in this disk.
		  This excludes same-element-filled pages (same_pages) since
		  no memory is allocated for them.
                  Unit: bytes
 compr_data_size  compressed size of data stored in this disk
 mem_used_total   the amount of memory allocated for this disk. This
                  includes allocator fragmentation and metadata overhead,
                  allocated for this disk. So, allocator space efficiency
                  can be calculated using compr_data_size and this statistic.
                  Unit: bytes
 mem_limit        the maximum amount of memory ZRAM can use to store
                  the compressed data
 mem_used_max     the maximum amount of memory zram have consumed to
                  store the data
 same_pages       the number of same element filled pages written to this disk.
                  No memory is allocated for such pages.
 pages_compacted  the number of pages freed during compaction
 huge_pages	  the number of incompressible pages

File /sys/block/zram<id>/bd_stat

The stat file represents device's backing device statistics. It consists of
a single line of text and contains the following stats separated by whitespace:
 bd_count	size of data written in backing device.
		Unit: 4K bytes
 bd_reads	the number of reads from backing device
		Unit: 4K bytes
 bd_writes	the number of writes to backing device
		Unit: 4K bytes

9) Deactivate:
	swapoff /dev/zram0
	umount /dev/zram1

10) Reset:
	Write any positive value to 'reset' sysfs node
	echo 1 > /sys/block/zram0/reset
	echo 1 > /sys/block/zram1/reset

	This frees all the memory allocated for the given device and
	resets the disksize to zero. You must set the disksize again
	before reusing the device.

* Optional Feature

= Physical pool observer

CONFIG_ZRAM_POOL_OBSERVER defaults off and requires DEBUG_FS. When enabled,
root can read /sys/kernel/debug/zram/zramX/pool_observer (with debugfs mounted).
This is diagnostic output, not a stable ABI. There is no polling worker, PSI
integration, writeback action, or writable control.

physical_pool_bytes is the zsmalloc page count times PAGE_SIZE. It does not
include the slot table or backing storage. Sampled pressure enters high at
768 MiB or above, returns to low at 512 MiB or below, and retains its last
sampled state in between. Each device starts in low pressure on initialization;
reset clears the latch and scan cursor. Reads of an uninitialized device
report pressure uninitialized and do not touch a pool or table.

With CONFIG_ZRAM_WRITEBACK, each initialized sample visits at most 1024 slots
from a per-device rotating cursor, skipping busy slots without waiting for
slot locks. eligible_slots counts matches of the existing filtered-idle
predicate with at least one cumulative idle marking. It does not require
backing to be attached and is not a whole-device estimate, a prediction of
reclaimable bytes, or an authorization to write. Pool occupancy and individual
slots can change during sampling. Without writeback, eligibility is unsupported.

With CONFIG_ZRAM_MEMORY_TRACKING as well, eligible_aged_slots counts eligible
slots whose recorded last access is at least 60 seconds before the sample,
using the existing boottime timestamp (including suspend). Missing timestamps
and ones newer than the sample are counted in eligible_age_unknown_slots.
Without both options the observer reports access_age unsupported; idle markings
are never treated as elapsed time. The observer does not mark slots idle.

= writeback

With CONFIG_ZRAM_WRITEBACK, zram can write idle/incompressible page
to backing storage rather than keeping it in memory.
To use the feature, admin should set up backing device via

	"echo /dev/sda5 > /sys/block/zramX/backing_dev"

before disksize setting. It supports only partition at this moment.
If admin want to use incompressible page writeback, they could do via

	"echo huge > /sys/block/zramX/writeback"

To use idle page writeback, first, user need to declare zram pages
as idle.

	"echo all > /sys/block/zramX/idle"

From now on, any pages on zram are idle pages. The idle mark
will be removed until someone request access of the block.
IOW, unless there is access request, those pages are still idle pages.

Admin can request writeback of those idle pages at right timing via

	"echo idle > /sys/block/zramX/writeback"

With the command, zram writeback idle pages from memory to the storage.
The bare "idle" command retains its original meaning: it does not filter by
compression savings or idle count. "huge" and "page_index=<index>" likewise
retain their original selection rules. Same-filled, already written-back and
under-writeback slots are excluded in all modes.

To explicitly select only idle pages with low compression savings, use:

	"echo 'idle 32' > /sys/block/zramX/writeback"
	"echo 'idle 32 3' > /sys/block/zramX/writeback"

The syntax is "idle <max_pages> [idle_count]", using single spaces and decimal
unsigned numbers, with an optional final newline. max_pages is required and
counts successfully installed backing pages in this request, not scanned pages,
I/O attempts or 4KB units. Zero selects no pages. idle_count defaults to 1;
values above 10 are clamped to 10. Zero removes only the count requirement:
the page must still have its IDLE and low-compression flags set. Extra arguments,
empty arguments, negative values and numeric overflow are rejected. There is no
implicit low-compression filter for the bare "idle" command.

The count is the cumulative number of "all" writes to idle seen by this object,
saturating at 10; it is NOT a count of consecutive idle generations or an elapsed
age. Access clears the IDLE flag but does not reset this existing counter.
Consequently, an accessed page can pass a higher count after being marked idle
again. Freeing/replacing the object (including successful recompression), or
writing "all" to new, resets the count. idle_stat reports allocated slots in
count buckets 1 through 10, even if their current IDLE flag is clear; new_stat
reports allocated slots in bucket zero. These statistics are not restricted to
low-compression pages. Slots under writeback are not marked by idle.

low_compress_ratio is a global setting shared by all zram devices, default 75,
and accepts 0..100. An in-memory, non-same-filled object is flagged low when
floor(100 * (PAGE_SIZE - stored_size) / PAGE_SIZE) is strictly less than the
setting. Zero disables classification for newly installed objects. Changing the
setting does NOT rescan or reclassify existing objects: their flags and the
lowratio_pages field (last column of mm_stat) retain installation-time meaning.
New writes and successful recompression classify the newly installed size using
a single snapshot of the current setting. Failed or skipped recompression keeps
the old classification. Disabling the setting therefore does not immediately
remove old low flags or exclude those old objects from explicit writeback.

Writeback gathers at most 32 pages in request-private buffers, using a
synchronous BIO only for consecutive backing-device page slots. A backing-slot
hole, a full batch, the per-request success bound or the end of the scan flushes
the batch. Memory pressure may reduce the batch size; failure to allocate even
one buffer returns ENOMEM. Page buffers need not be physically contiguous.
Requests on the same device are serialized. Reads retain the existing backing
read path. A slot freed, rewritten, accessed or explicitly marked new during
collection or I/O is not replaced by that writeback's saved contents.

The per-request max_pages counts successful installations, not physical I/O
attempts, and pending pages are included when enforcing that bound. It does not
replace the device writeback budget described below. A failed BIO (including a
partially completed BIO) installs none of its pages. An error or pending signal
cancels unsubmitted pages and releases temporary backing slots; earlier completed
batches are not rolled back. Signals observed after synchronous I/O also prevent
installation of that batch. Errors can therefore be returned after physical I/O
or earlier successful installations.

If there are lots of write IO with flash device, potentially, it has
flash wearout problem so that admin needs to design write limitation
to guarantee storage health for entire product life.

To overcome the concern, zram supports "writeback_limit" feature.
The "writeback_limit_enable"'s default value is 0 so that it doesn't limit
any writeback. IOW, if admin want to apply writeback budget, he should
enable writeback_limit_enable via

	$ echo 1 > /sys/block/zramX/writeback_limit_enable

Once writeback_limit_enable is set, zram doesn't allow any writeback
until admin set the budget via /sys/block/zramX/writeback_limit.

(If admin doesn't enable writeback_limit_enable, writeback_limit's value
assigned via /sys/block/zramX/writeback_limit is meaningless.)

The device budget is a physical-write-attempt budget in 4KiB units, not a count
of successfully installed backing pages. Immediately before submitting a BIO,
writeback reserves the whole submitted portion under wb_limit_lock. A batch is
truncated to the remaining whole-page budget; no BIO may overshoot it. On kernels
with pages larger than 4KiB, a remainder smaller than one page cannot be used.
Exhaustion returns EIO after any affordable part of the pending batch completes.
Reservations not submitted (for example, a signal or BIO construction failure)
are refunded. Submitted pages consume budget even on I/O error, partial device
completion, cancellation or concurrent slot invalidation: physical writes may
already have occurred, so these are not refunded.

Both writeback_limit and writeback_limit_enable stores wait interruptibly for
any current writeback request on this device to finish. Thus a new quota or
enable setting takes effect between requests, never midway through a reservation
or refund. Reading the remaining budget may show a current reservation. There
is no old-request refund into a newly configured quota. bd_stat's third column
counts submitted physical pages (including failed attempts), while its first
column counts successfully installed pages still on the backing device. Both
are reported in the existing 4KiB units.

If admin want to limit writeback as per-day 400M, he could do it
like below.

	$ MB_SHIFT=20
	$ 4K_SHIFT=12
	$ echo $((400<<MB_SHIFT>>4K_SHIFT)) > \
		/sys/block/zram0/writeback_limit.
	$ echo 1 > /sys/block/zram0/writeback_limit_enable

If admin want to allow further write again once the bugdet is exausted,
he could do it like below

	$ echo $((400<<MB_SHIFT>>4K_SHIFT)) > \
		/sys/block/zram0/writeback_limit

If admin want to see remaining writeback budget since he set,

	$ cat /sys/block/zramX/writeback_limit

If admin want to disable writeback limit, he could do

	$ echo 0 > /sys/block/zramX/writeback_limit_enable

The writeback_limit count will reset whenever you reset zram(e.g.,
system reboot, echo 1 > /sys/block/zramX/reset) so keeping how many of
writeback happened until you reset the zram to allocate extra writeback
budget in next setting is user's job.

If admin want to measure writeback count in a certain period, he could
know it via /sys/block/zram0/bd_stat's 3rd column.

= synchronous per-request writeback ioctl (optional)

CONFIG_ZRAM_WRITEBACK_IOCTL depends on CONFIG_ZRAM_WRITEBACK and defaults to n.
It adds ZRAM_IOC_WB_EXEC (_IOWR('Z', 0x20, struct zram_wb_exec)) and
ZRAM_IOC_WB_STATUS (_IOWR('Z', 0x21, struct zram_wb_status)) on /dev/zramX.
The definitions are in include/uapi/linux/zram.h. Version 1 has exactly 160-byte
EXEC and 192-byte STATUS structures, using fixed-width fields and 8-byte-aligned
64-bit values. Native and compat userspace have identical layouts and ioctl
numbers; there are no embedded pointers. Both zram block-operation tables expose
the same commands. CONFIG=n and unknown commands yield user-visible ENOTTY via
the block layer; known numbers with wrong direction/encoded size yield EINVAL
when enabled. No defconfig is enabled automatically.

Both commands require CAP_SYS_ADMIN. EXEC additionally requires a descriptor
opened for writing (otherwise EBADF); STATUS permits a read-only descriptor.
Zero the entire structure and set size = sizeof(struct ...) and version = 1.
All flags, reserved fields and output fields MUST be zero on input. A wrong size,
nonzero forbidden byte, invalid mode or invalid input combination returns EINVAL;
an unsupported version returns EPROTONOSUPPORT; copyin faults return EFAULT.
These failures perform no writeback. STATUS accepts only size and version as
nonzero inputs. Malformed input must not trigger a legacy-backend fallback.

STATUS returns capability bits, kernel page_size, actual disksize_bytes (not a
userspace configuration wish), nonzero instance cookie and generation, and
INITIALIZED/BACKING/GLOBAL_LIMIT state bits. Its capability mask advertises EXEC,
STATUS, FILTERED_IDLE and DUAL_LIMIT. The quota is sampled in 4KiB units; page
statistics, including bd_count/reads/writes, are in kernel pages, while compressed
and allocator memory use are bytes. Initialization, disk size and identity are
protected against lifecycle changes by init_lock. Quota and statistics are
individually sampled and can change during the call: there is no all-fields-
coherent snapshot, no last-request result and no guarantee that state stays ready
after the call. An uninitialized device still supports STATUS; lack of readiness
is not evidence of an unsupported ioctl ABI.

EXEC requires a nonzero request_id and the expected_instance/expected_generation
returned by STATUS. The ID is returned unchanged for correlation only: there is
no deduplication cache, ownership protocol or exactly-once guarantee. A repeated
ID executes a new request. A mismatched instance/generation reports
STOP_STALE/op_errno=-ESTALE without work. Matching identity but no initialized
device or backing device reports STOP_NOT_READY/op_errno=-ENODEV. These are valid
structured results (ioctl returns 0), including for a zero-budget request.

Modes PAGE, HUGE, IDLE and FILTERED_IDLE preserve the corresponding sysfs selection
rules. page_index is zero except in PAGE mode, where slot zero is valid; values
above U32_MAX are rejected, and an index beyond current capacity reports EINVAL
in the result. idle_count is 0..10 for FILTERED_IDLE, and zero for every other
mode. FILTERED_IDLE still requires current IDLE and low-compression flags; count
zero removes only the cumulative-count threshold, not these flags. Unlike the
legacy sysfs parser, ioctl rejects rather than clamps a count greater than 10.

max_attempt_pages bounds physical pages submitted by this call, including failed
or partially completed BIOs and pages later invalidated. max_installed_pages
bounds successful slot installations. Both use kernel pages, must be positive for
work, and max_installed_pages must not exceed max_attempt_pages. If either is zero
there is explicitly no work (STOP_NO_WORK/op_errno=0, no scan/allocation/I/O),
subject to input, identity, readiness and page-index validation. In particular,
zero does not mean unlimited; a zero attempt cap with a positive installation
cap is invalid. Pending snapshots count against both bounds, so neither can be
overshot by a batch. Request attempts are independent of the global quota; EXEC
never enables/disables it, replaces it, silently refills it or turns it into a
per-request quota. When globally enabled it still limits every physical attempt
using the reservation/refund rules above. Disabled global limits do not disable
the per-call limits. Exhaustion reports STOP_GLOBAL_LIMIT/op_errno=-EIO after any
affordable partial batch, and is not silently retried.

EXEC returns these request-local outputs:
  scanned_pages     slots examined by the scan (including noncandidates), once
                    per slot; the preselection recheck is not a second scan.
  selected_pages    slots claimed UNDER_WB after the final selection check,
                    including a selection whose snapshot read subsequently fails.
  submitted_pages   physical pages passed to submit_bio_wait, not BIO count.
  installed_pages   increments at each successful slot installation under the
                    slot lock; never a difference of global bd_count samples.
                    A later free of an installed page does not reduce this count.
  invalidated_pages selected slots whose allocation/UNDER_WB/IDLE identity guard
                    fails when finalized, counted once, before clearing flags.
                    Includes invalidated unsubmitted snapshots. Read/IO/signal/
                    budget cancellation alone does not count as invalidation.
  duration_ns       elapsed monotonic time from after input validation through
                    execution and cleanup, including lock waits but not copyout.
  stop_reason       COMPLETE, NO_WORK, ATTEMPT_LIMIT, INSTALLED_LIMIT,
                    GLOBAL_LIMIT, BACKING_FULL, INTERRUPTED, ERROR, STALE or
                    NOT_READY (STOP_NONE is only the zero input value).
  op_errno          zero or negative errno; never a positive errno.
  error_stage       NONE, ALLOC, SNAPSHOT_READ, BIO_BUILD or IO, distinguishing
                    otherwise identical errno results. Non-error stop causes
                    and lifecycle/validation-result errors use NONE.

COMPLETE means the scan ended, not that a nonzero installation goal was reached.
When both per-call caps are reached, INSTALLED_LIMIT takes precedence. Real
errors/signals/global exhaustion take precedence over ordinary cap/end-of-scan
reasons, and cleanup does not overwrite the first error, stage or stop cause.
An IO error is preserved if a signal is also noticed after the same BIO. A
signal is reported as op_errno=-EINTR, never a restartable syscall result.

All structurally valid EXECs return ioctl 0 after copying their result, even if
op_errno records stale/not-ready, ENOSPC, ENOMEM, EIO, EINTR or another operation
error. Callers must inspect BOTH syscall return and op_errno. Errors may follow
physical writes or successful earlier batches; they do not roll back those
effects. A copyout failure returns syscall EFAULT even after effects and may
leave only a prefix of the result in userspace. Submitted quota stays consumed;
there is no refund, internal restart or result recovery API. The caller must not
automatically replay EXEC or fall back to sysfs after EFAULT or any other EXEC
failure. STATUS cannot resolve whether a particular request installed pages.

The engine is shared with legacy sysfs, uses the existing synchronous 32-page
aggregation and init_lock -> wb_mutex -> slot/wb_limit_lock order, and preserves
the UNDER_WB/IDLE invalidation protocol. There is no new worker, parallel BIO,
slot-owner system, or sleeping lock in slot-free notification. Old sysfs parsing,
selection, unlimited-attempt behavior, returns and global-limit behavior remain.

A new device has a random nonzero instance cookie and generation 1, stored outside
resettable statistics. Successful backing setup/removal, disk initialization and
accepted reset/removal advance generation under exclusive init_lock. Accepted
reset advances it even on the uninitialized early return (whose legacy backing
cleanup behavior is unchanged). Rejected lifecycle operations do not advance it;
normal stats updates and quota setters do not advance it. An operation may cause
more than one increment (for example reset also removes a backing device); use
equality, not an expected increment. Generation wrap creates a different random
nonzero instance cookie and starts at generation 1; device ID reuse also obtains
a new random cookie. Tokens are lifecycle guards, not security credentials or
per-slot versions. Exclusive reset waits for the synchronous engine to finish.

Host-only actual-source regression targets and their simulation limits are
listed in tools/testing/selftests/zram/README. Passing them is not a full kernel

= memory tracking

With CONFIG_ZRAM_MEMORY_TRACKING, user can know information of the
zram block. It could be useful to catch cold or incompressible
pages of the process with*pagemap.
If you enable the feature, you could see block state via
/sys/kernel/debug/zram/zram0/block_state". The output is as follows,

	  300    75.033841 .wh.
	  301    63.806904 s...
	  302    63.806919 ..hi

First column is zram's block index.
Second column is access time since the system was booted
Third column is state of the block.
(s: same page
w: written page to backing store
h: huge page
i: idle page)

First line of above example says 300th block is accessed at 75.033841sec
and the block's state is huge so it is written back to the backing
storage. It's a debugging feature so anyone shouldn't rely on it to work
properly.
